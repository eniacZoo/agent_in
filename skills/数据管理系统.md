# 数据管理系统

人读、人改。模型用 `read_file` 打开本文件。适用于：前后端分离、可编辑的本地数据展示。先读本文件，再把 `skills/templates/webapp/` 整份复制到交付目录里改，不要从空白页面写起。

## 技术栈（都已离线备好，禁止 pip / npm）

- 后端：FastAPI + SQLite。包在 agent_in 的 `vendor/`。启动时 `PYTHONPATH` 指到该目录，或用环境变量 `AGENT_VENDOR`。
- 前端：Vue 3 全局构建 + ECharts，免构建。文件在 `vendor/web/vue.global.prod.js`、`vendor/web/echarts.min.js`。复制到交付项目的 `frontend/vendor/`。
- 字体只用系统字体栈（微软雅黑、Segoe UI），不要引 CDN。

拆分和入库的规则见 `skills/数据拆分入库.md`。页面做完用 `skills/网页验收.md` 在 1440 和 390 两种宽度下截图自查。

## 复制脚手架之后必须有的能力

列表：筛选、搜索、排序、分页。
详情：按业务分段，每段可以单独编辑、取消、保存。原文和结构化字段上下对照，原文默认只读。
编辑：前端做类型校验（整数、小数、日期），后端再校验一次。子表行可以增删。
审计：`edit_log` 记下字段、改前、改后、时间。只记字段名不算审计。
导出：导出的版式跟原表一致，不能把用户没改过的单元格改写一遍。
看板：至少一个 ECharts 图，用已经结构化的数值，不要在前端再解析长文本。

## 设计

沿用脚手架的 CSS 变量，不要另起一套内联样式。

- 背景 `--bg`，纸面 `--paper`，正文 `--ink`，强调 `--accent`，正负用 `--ok` / `--bad`
- 正文字号 14px，行高 1.5。数字用等宽
- 1440 宽是表；390 宽是单列卡片，筛选区折行，不要横向撑破
- 有未保存修改时，离开该段要提示

## 工程

```
交付目录/
  start.bat          检查依赖、等端口、打开浏览器
  backend/app.py
  frontend/index.html
  frontend/app.js
  frontend/style.css
  frontend/vendor/   vue 与 echarts
  data/app.db
```

`start.bat` 用 `py -3.14`。不要假设当前目录，先 `cd /d %~dp0`。端口被占用就换端口并写进最后的说明。

## 完成之前

用工具打过这些请求再汇报：列表条数等于导入条数、改一个字段后再读回来、审计里有旧值和新值、导出文件能打开。然后按网页验收技能看两张截图。缺任何一项就不要说做完。
