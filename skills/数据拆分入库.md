# 数据拆分入库

人读、人改。模型用 `read_file` 打开本文件。适用于：把 Excel / CSV 里的长文本拆成结构化字段，写入 SQLite，并能量出拆分是否丢数。

## 先做一次结构普查，再写解析器

用 python 工具跑一份普查，不要一个疑问一个脚本。普查至少打出：

- sheet 名、维度、合并单元格、隐藏列、冻结窗格、表头在第几行（不要把第 1 行分组标题当成列名）
- 每列的类型：数值、日期、文本、公式。公式列必须 `data_only=True` 再读一遍，拿到缓存值；读不到就在报告里写明
- 空值数量、重复键、数字存成文本（如 `1/25`）、混用单位（万/亿）、占位符（`/`、`xx`、`未参评`）
- 长文本列的分段规律：抽 3 行全文，再统计每个小节标题在全部行里出现的次数

把普查结论写进 task_temp/task_notes.md。列映射一旦清楚就写解析脚本，不要继续堆 probe。

## 表怎么拆

一层只拆到「一、二、三」太粗。推荐：

1. 主表：一行一条业务实体，保留全部原始列。数值和单位分开存（`35.54` + `亿`），展示时再格式化。排名 `n/N` 拆成 rank、total，原文保留。
2. 长文本：先按固定段落切开，每段留原文。
3. 段内条目：编号项、小结、结论各一行，留原文。
4. 能稳定解析的明细（指标名、本值、均值、排名）再进子表。解析不了的写进 notes，不要丢。

每张子表用外键连回主表，并留 `raw` 原文。重新导入会覆盖用户编辑时，必须在交付说明里写清楚；做得到的话，导入前把 edit_log 里改过的字段排除在覆盖之外。

## 字段级覆盖率，而不是「有没有这一行」

解析器跑完全表后，用 SQL 对账，至少包括：

- 实体数 = 源表数据行数
- 某个小节在原文里出现的次数 = 解析出的非空条数。原文里本来没有的，记成「源数据缺失」，不要算成解析成功
- 抽查每种异常至少 1 行：缺字段、负值、单位混用、占位符、括号里夹了别的内容导致提前截断
- 禁止把校验改成用解析结果拼回原文再比对（那一比对永远是 0）。校验失败就改解析器

覆盖率没对齐之前，不要开始写界面。
