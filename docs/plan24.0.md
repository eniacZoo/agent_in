# agent_in v24.0 — vendor 用 3.11，无产出刹车 30 轮

> 前置：plan23。vendor 的原生扩展是 CPython 3.11 win_amd64。系统默认若是 3.14，直接拿当前解释器会加载失败。

## 做了什么

1. **解释器**  
   当前已是 3.11 时，shell 用 `sys.executable`，不再去问启动器。否则用 `py -3.11` 解析真实路径，并把该目录加到子进程 `PATH` 前面。找不到 3.11 时不假装成功，并提示改用 `py -3.11`。

2. **刹车**  
   已经开始改文件之后，连续 30 轮没有新产出才停（`STALL_STOP_ROUNDS = 30`），10 轮先警告。只探查、还没改文件时不按这 30 轮停。模块上的 `MAX_TOOL_ITERATIONS` 仍是 80，供旧测试读取；运行时上限见 plan27 的 provider profile。

## 验收

- [x] 3.11 直接用当前解释器
- [x] 非 3.11 走 `py -3.11`；找不到则返回空
- [x] 第 30 轮且已经在改文件时 `should_stall_stop` 为真；第 29 轮或尚未改文件时为假
