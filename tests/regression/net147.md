# 147 家网点回归场景

用来看 harness 改完之后，长任务还有没有变好。不要拿它当功能测试，它会真的调模型。

## 任务原文

通览工作目录里的《147家网点诊断分析总表.xlsx》。把表格内容（含 AC 列从第 3 行起的汇总文本）拆进数据库，做一个前后端分离、可编辑的数据展示。先规划，跟用户确认后再做。

## 怎么跑

在 agent_in 目录下，工作目录指向放了这份 xlsx 的文件夹。

```
py -3.14 agent.py --provider default -w <工作目录> --session-id reg-ds "<任务原文>"
py -3.14 agent.py --provider office  -w <工作目录> --session-id reg-qwen "<任务原文>"
```

office 是本地 Qwen。跑完：

```
py -3.14 tests/regression/score_session.py sessions/reg-ds.json
py -3.14 tests/regression/score_session.py sessions/reg-qwen.json
```

## 基线（2026-10-03，改 harness 之前）

`score_session.py sessions/bc657821.json`（模型 deepseek-v4.1-flash）读到：

- 撞上「达到最大工具调用轮数」1 次，靠用户再说才做完
- 同一路径重读 45 次。最多的是 `build_db.py` 22 次、`server.py` 15 次

- 会话里没有 telemetry（当时还没记缓存命中）

同一天、同一个模型，PI 用 131 次工具调用做完，缓存命中约 98.7%，没有撞轮次上限。

## 看什么

- 是否一次做完，不需要用户说「请继续」
- tool_calls 是否接近或低于 153，reread_reads 是否明显下降
- telemetry.cache_hit / telemetry.prompt_total 是否高于 0（DeepSeek 应接近 PI 的 98%）
- telemetry.truncations 是否为 0
- 字段覆盖率：核心指标约 854 项（按原文「指标名+本值/均值+排名」计数，不是 859）。可比同业排名、负营收、低于平均的客流不能再整列丢
- 页面按 skills/网页验收.md 在 1440 和 390 下看过

这次改造不代替跑这一轮。数字以 score_session.py 的输出为准。
